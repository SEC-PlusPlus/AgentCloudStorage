# M5 开发文档：大文件分片上传与续传

状态：已实现（2026-10-05）；生产构建待验证，真实大文件端到端联调待后端依赖启动后完成。

## 目标

让文件工作台调用现有 Go 分片上传接口，上传超过普通接口 50 MiB 上限的文件，并能查看进度、取消和在网络中断后续传。

## 设计原则

- 延续 GoVault 的深色、低装饰界面；像素 Go 鼠作为识别元素，避免重复使用渐变卡片、粒子、光环和无实际含义的英文标签。
- 进度、失败、重试和取消状态都来自真实上传状态，不伪造进度。
- 第一版串行处理文件与分片，不做并发分片、断点自动恢复后台任务或 Redis 上传状态缓存。

## API 流程

1. 对达到 49 MiB 的文件请求 `POST /api/v1/uploads`，提交 `folder_id`、`original_name`、`content_type` 和 `size`，读取返回的会话 ID、分片大小和过期时间。
2. 用 `File.slice()` 按服务端返回的分片大小切片，通过 `PUT /api/v1/uploads/:id/parts/:number` 以原始二进制请求体逐片上传。
3. 通过 `GET /api/v1/uploads/:id` 读取服务端已记录的分片号，计算已完成字节数和真实进度。
4. 所有分片完成后请求 `POST /api/v1/uploads/:id/complete`；成功后刷新当前目录和存储用量。
5. 用户取消时中止当前网络请求，并调用 `DELETE /api/v1/uploads/:id` 清理会话；接口冲突或网络错误须展示可理解的状态。

小于 49 MiB 的文件继续走 `POST /api/v1/files` 普通上传接口；达到 49 MiB 时改走分片接口。后端 50 MiB 限制作用于整个 multipart 请求体而非单独文件，预留 1 MiB 可避免表单边界开销导致临界文件被拒绝。

## 续传行为

- 浏览器本地只保存会话 ID、文件名、大小、最后修改时间、目标文件夹和到期时间，不保存文件内容或访问令牌。
- 页面刷新或网络中断后，提示用户重新选择原文件；通过文件名、大小和最后修改时间核对后，用进度接口查询已上传分片，只补传缺失分片。
- 如果会话不存在、已过期、已取消或文件信息不匹配，提示用户重新开始，不尝试猜测或复用其他上传会话。
- 清除已完成、已取消、无效或已过期的本地会话记录。

## 文件范围

- `web/src/api/storage.ts`：普通上传与大文件分片流程 API。
- `web/src/pages/FileWorkbench.vue`：选择分支、上传进度与状态交互。
- 如实现需要，新增轻量上传 composable；不引入大型上传库。
- `web/src/api/client.ts`：补充分片 API 的错误映射。

## 验收标准

1. 小于 49 MiB 的文件走普通上传；达到 49 MiB 的文件使用分片接口。
2. 使用 60 MiB 以上真实文件上传成功，文件列表能看到记录，下载内容与源文件一致。
3. 上传一部分后刷新页面并重新选择同一文件，只补传未完成分片，最终文件完整。
4. 取消上传后界面状态更新；服务端会话取消，不生成正式文件。
5. 未登录、配额不足、网络中断、会话过期等错误有清楚提示，成功操作后列表刷新。
6. `npm run build` 通过，并完成本地前后端、MySQL、MinIO、Redis 联调。
