# M2 开发文档：文件工作台

状态：已实现（2026-10-03）。

## 目标

登录后展示当前目录文件与文件夹，并支持基础日常操作。界面调用现有 Go API，不虚构后端尚未支持的行为。

## 页面与交互

- 用侧栏/顶部区域呈现“我的文件”，根目录显示文件和文件夹列表、名称、类型、大小、更新时间。
- 支持进入子文件夹、返回根目录、展示当前目录位置。由于目前 API 没有目录祖先链查询，进入深层后仅准确显示当前目录名称及“返回上级”操作，不伪造完整面包屑。
- 支持新建文件夹、单文件上传（展示进度或忙碌状态）、下载、重命名、移动和移入回收站。
- 上传成功、改名、移动或删除后刷新当前目录数据；所有错误用清晰中文提示。
- M5 接入分片上传后，小于 49 MiB 的文件走普通上传；达到 49 MiB 的文件改走分片 API，最终仍以服务端响应为准。
- 空目录和首次使用状态设计简洁，继续沿用暗色轨道云仓与像素风微装饰；像素元素不影响文件名称可读性。

## API 使用范围

- `GET /api/v1/files?folder_id=&page=&page_size=`
- `GET /api/v1/folders?parent_id=`
- `POST /api/v1/folders`
- `POST /api/v1/files`
- `GET /api/v1/files/:id/content`
- `PATCH /api/v1/files/:id`、`PATCH /api/v1/files/:id/move`、`DELETE /api/v1/files/:id`
- `PATCH /api/v1/folders/:id`、`PATCH /api/v1/folders/:id/move`、`DELETE /api/v1/folders/:id`

上传以 `multipart/form-data` 发送文件，不能手动设置 multipart 的 `Content-Type`，让浏览器生成 boundary。具体列表与上传字段需按 handler 实际响应结构核对后实现。

## 不在 M2 范围

搜索、回收站页面、永久删除、分片上传、断点续传、秒传、在线预览、分享、批量操作和 Agent 知识库。

## 验收标准

1. 可通过登录进入工作台，根目录与嵌套目录内容正确展示。
2. 新建文件夹、上传、下载、重命名、移动、软删除均只调用已有 API。
3. 成功操作后目录刷新，失败有可读提示；401 清理会话并回到登录页。
4. 桌面和窄屏视口可完成主要操作，文件名与操作入口不发生横向溢出。
5. 构建通过；后端运行时完成真实 API 手动联调。

## 实现说明

文件工作台现已实现目录列表、创建文件夹、单文件上传/下载、重命名、移动、软删除及相应加载/错误/空状态。搜索与回收站由 M3 补充，虽然最终复用工作台工具栏。
